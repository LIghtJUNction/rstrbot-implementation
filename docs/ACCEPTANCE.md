> **0.2.0 更新：** 新增界面重设计、邮箱、Google 登录与多 Passkey 管理；改动与独立验收见 [0.2.0 报告](IMPROVEMENTS_0_2_0.md) 和 [账号配置指南](AUTHENTICATION.md)。原设计包保持不变。下方是历史的 52 项广范围追踪，不能将新增登录能力或旧测试累计为整项完成；旧粒子登录展示已被新静态品牌界面替换，相关历史描述不代表当前 UI。

> **0.1.3 更新：** 本轮仅推进认证、运行派发和 WebUI 的可靠性边界，完整需求的完成分类不变。新增实际验证见 [0.1.3 改进报告](IMPROVEMENTS_0_1_3.md) 和 [本轮回执](evidence/v0.1.3/)。下文 0.1.2 数量与程序摘要保留为历史基线，不自动算作新版本验证。

日期：2026-10-28（Asia/Taipei）。设计基线：`docs/blueprint/BUILD_PROMPT.md` 1.0。

**本次交付为可运行的 0.1.2 开发预览，完整第二阶段设计仍未全部实现。** 52 项原需求保留为 **41 项部分实现、9 项未实现、1 项桌面源码待原生验收、1 项追踪已保留**。这些原需求每项包含多个能力和故障边界，不能把一次局部测试通过算作整项完成。

“部分实现”表示表内具体行为已有代码，但完整合同仍有缺口；“源码待验收”表示没有对应平台运行证明；“未实现”不会以空成功或假数据替代。底部逐项列出剩余范围。

## 仍然阻止“完整第二阶段完成”声明的事项

1. **P0 边界没有全部完成。** 当前只读通用工具与明确可用的扩展可以使用；任意副作用工具审批、附件隔离、通用沙箱、完整灾备等仍未交付。
2. **三平台不能互相替代。** Linux 上的真实服务/插件测试不是 Windows named pipe、macOS 签名或桌面安装/退出证明。
3. **兼容不是架构名称。** 旧插件、旧 HTTP、OpenCode 和 Pi 没有冻结真实样本的验收，不标记支持。
4. **真实外部服务仍需凭据与测试范围。** diagnostic 是明确的测试夹具；本地 HTTP 上游验证不是实际商业供应商费用或聊天平台账号验证。
5. **备份范围必须跟产物走。** 当前可迁移的 JSON 快照保护数据库事实，单独的 secrets.key 与外部状态必须另外保护。恢复默认暂停执行，未知费用与副作用不能自动归零或重发。
6. **性能数据不能补造。** 打包体积和 gzip 数据与固定硬件的性能测量是不同证据。完整负载、故障和容量数据尚需补齐。
