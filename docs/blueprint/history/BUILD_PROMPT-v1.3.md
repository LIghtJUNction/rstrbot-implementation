# RstrBot 构建提示词

版本：第二阶段设计基线 1.3 · 2026-10-28

本文件是 RstrBot 后续开发的独立输入。它规定产品、行为、边界和验收结果，不包含实现代码。本轮仅交付设计；以下“必须”“应当”均为待实现目标，不代表已有功能或已通过测试。旧阶段源码只作归档，不作为新项目必须延续的内部结构。

## 1. 产品是什么

RstrBot 是一个让个人和团队把聊天渠道、模型、工具与自己的资料接在一起，并可靠地完成对话和任务的应用。

本质上，它接收一条消息，确定谁有权使用哪些资料和工具，安排一次执行，再把结果送回正确的人。复杂性主要来自多人同时使用、第三方服务不稳定，以及操作已经发生但回执尚未保存的情况。

产品名、桌面应用名和品牌统一为 **RstrBot**；核心程序名为 **rstrbot**。核心使用 Rust。宣传、首页和新 API 围绕 RstrBot 自身的用途组织。旧生态名称只出现在可选兼容插件、迁移说明、测试样本与来源附录中。

目标用户包括个人助手使用者、群聊机器人维护者、小团队管理员、插件开发者，以及使用 HTTP、SDK 或 MCP 接入的应用。支持个人桌面、本机后台服务和多人服务器部署。

## 2. 必须成立的产品原则

1. **多用户是基础。** 个人安装也使用同一套用户、工作区、权限和数据所有权规则，只是默认创建一个用户和一个工作区。
2. **核心小，扩展完整。** 身份、授权、运行记录、资源限制、插件监管和可靠投递由核心负责；模型供应商、平台适配器、语言运行时、加载器、检索后端和任务执行器通过稳定协议扩展。
3. **失败要说清发生在哪。** 模型没生成、工具没执行、消息没送达、记录没保存，是不同结果。不能把已经发生的外部操作重新标为“什么都没做”。
4. **权限由服务端执行。** 提示词、工具是否展示、前端隐藏按钮、模型承诺，都不能代替授权。代理、插件和子代理不能自行扩大权限。
5. **默认轻量，按需增加成本。** 未使用的语言运行时、向量模型、图表编辑器、语音和粒子渲染不常驻。可选服务故障不得意外扩大权限或预算。
6. **成熟工具优先。** 使用维护中的协议、SDK、数据库驱动、身份组件、任务和打包设施。确有差异时写清公共契约，避免为统一外观重造已有基础设施。
7. **兼容需要证据。** 不用空实现、永远成功的返回值或隐藏失败满足测试；按版本、功能和真实插件分别声明兼容范围。

## 3. 首次初始化与运行模式

初始化应依次完成部署用途、管理员建立、数据库选择、可选加速服务、数据位置和首个工作区设置。提供连接测试、明确错误和返回修改，提交前不破坏已有数据。

数据库必须同时支持 SQLite 与 PostgreSQL，功能语义一致。桌面和小规模单实例默认推荐 SQLite；多人共享服务器允许直接选 PostgreSQL。选择不应隐藏在高级配置文件里。

Valkey 是独立可选项，默认关闭。关闭时聊天、权限、工具、知识库、计划任务和事件恢复仍可使用。启用后可优化缓存、在线状态、通知和软限速；持久业务记录、权限、硬预算与任务是否执行过，不能仅保存在 Valkey。

首次管理员只能由持有初始化证明的人建立，不能让公网第一个访问者接管实例。提供本机控制台或受控部署渠道获得的短期一次性初始化凭据。已初始化实例拒绝重走首次接管流程。

桌面提供“本机工作区”和“连接已有服务器”两种模式。连接远程服务器时不自动启动另一个本地数据库和核心。服务部署默认仅开放明确配置的监听地址，远程访问须完成认证和加密配置。

## 4. 用户、工作区与权限

用户可以加入多个工作区。工作区拥有机器人连接、代理、模型连接、知识库、插件实例、定时任务、预算和审计记录。会话可以是个人私有、授权群组共享或显式分享；加入工作区不自动获得每个人的私聊。

默认角色为所有者、管理员、操作员、成员和只读查看者。实例管理员负责部署、升级和容量，日常界面不默认展示所有私人内容；宿主系统管理员的技术访问能力必须如实说明，不能宣称应用权限阻止了宿主 root 读取磁盘。

平台发送者、登录用户、机器人账号和服务凭据使用不同身份。绑定外部账号需要验证，不能用昵称或可猜测的用户 ID 合并身份。请求的工作区与权限来自可信认证上下文；客户端、模型或插件提交的标识不能覆盖它。

工作区成员撤销、凭据撤销、插件停用后，所有新操作和排队任务都必须重新检查权限。正在运行的流和子任务按资源租约取消，已完成的外部副作用保留真实回执。

凭据支持个人持有、工作区共享和服务账号授权。共享的是调用能力，默认不向成员、插件或模型返回明文密钥。加密密钥与业务数据分开管理，支持轮换、撤销、恢复和脱敏诊断。认证优先复用成熟方案；提供本地账户与恢复流程，支持可选 OIDC、Passkey 等接入而不把在线身份平台设为运行前提。

个人 API Key 的有效权限始终是签发范围与所属用户当前权限的交集，移出工作区或降权后同步收缩。服务身份的凭据以该服务身份当前授权为准，创建人只用于审计；正式移交后不依赖原管理员仍在职。

普通工具插件只取得受限调用能力。模型和平台插件优先使用限定目标、用途与有效期的凭据代理；必须直接处理签名、刷新或专有认证的受信任组件需单独授权和隔离，不得把秘密交给同语言运行时内的其他插件。核心不因此内置所有供应商业务协议。

## 5. 数据、迁移与恢复

SQLite 与 PostgreSQL 必须通过同一套行为验收，包括并发建会话、成员隔离、撤权、插件数据、流式记录、任务认领和备份恢复。数据库差异由存储边界处理，不能传播到业务插件。

SQLite 面向单核心实例，使用受控并发和短事务；网络模型调用、插件等待和媒体处理不能占住数据库事务。暴露写入排队、事务耗时、WAL 大小和磁盘余量，不用无界连接池解决写冲突。PostgreSQL 支持更高并发；多副本部署必须另行证明任务认领、租约、旧实例隔离和共享附件一致性。

数据目录遵循操作系统规范，配置、状态、缓存、日志、插件程序和用户文件分别有明确位置。支持用户明确选择便携数据目录，但不能依赖启动时的工作目录。插件更新不覆盖插件数据。

提供 SQLite 与 PostgreSQL 之间的受控迁移：预检查、备份、暂停写入、导入、校验、切换、失败恢复。未验证前不能删除来源；迁移失败可重试；不得承诺未经验证的无停机双向迁移。

完整备份包含数据库、会话、知识库原文与索引身份、附件、插件版本和数据、配置、任务与路由。密钥按独立保护策略处理。恢复先校验归属、版本、完整性和路径，在新目标或暂存位置演练，再显式替换。工作区导出与全实例灾备是不同权限；不把别的工作区内容带入普通导出。

备份必须具有可解释的一致性时点，通过暂停相关写入或已提交检查点和不可变资源清单实现。必要插件状态无法导出时标记不完整。恢复后先暂停外部副作用、计划任务与平台收发，核对运行意图、回执和连接身份，再启用；未知操作不能被恢复成一项全新待执行任务。

## 6. 插件体系

插件是能声明能力、配置、权限和生命周期的独立组件，不要求与核心使用同一种语言。核心不加载第三方不稳定 Rust 动态 ABI，也不把 Python 解释器作为基础依赖。

区分“安装包”“工作区中的插件实例”“实际运行进程”。同一安装包可被多个工作区使用，但配置、数据、凭据与执行授权各自独立。默认按工作区和插件实例隔离；进程独立只提供故障边界，面对不可信代码还需要操作系统隔离或独立部署。

提供 Python、Rust、C#、TypeScript SDK，覆盖发现、配置、事件、工具、模型、平台、任务、取消、错误和诊断。四种 SDK 运行相同协议测试，不允许某一语言依赖核心内部对象才能完成常规能力。

安装 Python 插件时安装 Python 运行时插件；其他语言同理。Python 原生加载器本身也是插件，优先用标准包入口点发现插件，使用 uv 管理独立依赖环境；开发工具链默认使用 mise。插件依赖不能污染核心进程或其他插件。

原生 Python 加载器、旧版兼容加载器、OpenCode 插件加载器、Pi 插件加载器分别提供。它们转译已有插件的公共行为，不能假定不同生态的所有 API 都可一一映射；无法映射的能力明确诊断。旧内部对象仅在兼容环境提供版本化代理，不进入新 SDK 的公共设计。

安装、启用、配置保存、运行、升级和回滚是可区分状态。提供版本锁定、变更说明、能力差异和失败恢复。新增权限须按同一规则处理，无论安装入口是 GUI、CLI、API 还是助手。禁用或卸载必须撤销工具、命令、事件、HTTP 路由、后台任务和凭据租约。

依赖准备、进程启动、协议握手和正常调用分别限时并显示状态。暂时失败有上限地退避重试，用户无需改变配置也能手动重试；永久错误停止自动重启。取消、超时与失败都必须回收所属进程树。

不要求中心插件仓库。支持仓库 URL、安装包、组织目录和可选索引。清单与搜索别名保留 astrbot_plugin 兼容标识；GitHub topic 使用符合其规则的 astrbot-plugin，原生插件使用 rstrbot-plugin。兼容现有插件索引并显示来源、版本与校验结果，标签本身不是可信身份。

## 7. 通信、API 与平台适配器

同机优先 Unix domain socket；Windows 使用仅授权用户可访问的 named pipe。远程使用认证加密连接。不能为获得平台一致性而把所有进程间调用改成公开 TCP 端口。

协议两端分别拥有明确的角色、能力和请求权限。通过版本协商和能力发现接入；明确请求、响应、事件、取消、错误、超时、流结束、重连及恢复语义。主控与工作进程之间不共享可变内部对象；子进程发回的身份或时间戳不能自行成为授权或截止时间的依据。

HTTP、CLI、WebUI、SDK 和 MCP 使用同一套业务操作、参数校验、身份规则和错误含义。API 必须区分服务支持、调用者获准和当前可用三种能力。提供机器可读接口规范和版本兼容政策。

平台适配器处理连接、事件转换、消息发送、附件、命令注册和平台回执，全部作为插件。逻辑会话 ID 与真实投递地址分开，跨会话主动推送使用经过授权的持久路由，重启后仍可恢复。

同一个平台适配器应能单独启动为 MCP 服务。复用同一业务逻辑，但以独立服务身份、权限和凭据运行。发送目标必须从授权范围选择；外部调用者不能仅凭字符串把消息发往任意账号。

兼容插件保留旧 HTTP 的方法、认证、错误、分页、流和副作用语义。提供完整路由清单、契约测试与明确的覆盖情况；不把只返回状态码或空对象称为“全量兼容”。旧 WebUI 若作为兼容选项，必须有浏览器端到端验证；主界面使用 RstrBot 新设计。

## 8. 对话、Agent 与工具

完整支持流式生成、自动多轮工具执行、工具结果回传、模型续轮、子代理和后台任务。每轮有确定的预算、步数、截止时间、取消和唯一执行终态。达到工具上限后可以生成收尾说明，但收尾不得重新开放副作用工具。

工具按只读、可幂等写入和不可安全重放分类。执行前校验身份、工作区、资源和参数；必要的确认绑定具体操作和参数。模型输出只是提议。超时或断线后结果不确定时先查询与核对，不自动重复发消息、写文件、下单或执行其他写入。

普通文本中的工具名不构成调用。连续没有有效进展、重复无效参数或反复得到同一结果时，在通用轮次耗尽前有界终止，并显示原因和已完成结果。失去授权或租约后拒绝新的副作用申请；已经进入外部发送阶段的操作按在途或未知处理，只有目标侧支持相应保证时才承诺可靠撤销或去重。

模型供应商全部插件化，支持本地与远程模型及多种协议。协议转译保留工具调用 ID、顺序、多模态、供应商签名和推理状态；切换模型不伪造目标供应商专有数据。支持按任务选择生成、快速决策、嵌入、重排、语音等模型。

记录每次模型请求的来源、用途、失败、重试和缓存用量。缺失 usage 或价格时显示未知，不显示伪造的零费用。预算在并发请求前预留，并在实际结果到达后结算；没有可靠计费信息时不能声称绝对精确的费用硬上限。

保留完整会话记录，将模型本轮输入视为可重建的投影。摘要、暂时提示、示例人格和真实消息明确分开；摘要保存来源范围和版本，重启后可恢复。压缩不删除永久历史，不破坏工具调用与结果配对。停止、重置、新会话、删除是不同操作，迟到结果不能复活被清空的状态。

群聊需要可解释的回复策略：提及、直接回复、命令、轻量判断、安静时段、冷却、机器人回声与频率上限。持续选择不回复时推进处理游标，不能积压后强制触发昂贵模型；“保持安静”不意味着删除消息历史。人格提供继承、解除、热更新和在途配置快照。

群聊、私聊和具体会话可以分别覆盖策略并显示继承来源。已接收、已消费、已回答分别记录。自身消息回声可以入历史，但默认不启动新轮次；用户合法引用机器人先前消息仍然允许。

## 9. 任务、知识与媒体

计划任务支持一次性、固定间隔和带 IANA 时区的日历计划；明确夏令时、错过执行、暂停、重启补跑、取消和多目标结果。一个计划时间点只有一个有效认领；执行时再次验证所有者权限。任务由数据库持久保存，Valkey 重启不能使它丢失。

后台任务结果可以主动推送到已授权会话，并记录生成、投递和持久化的独立进度。用户回复主动消息时能立即获得相应上下文；没有平台回执时明确“投递未知”。

知识库支持文件和受控 URL 导入、解析、分块、嵌入、索引、检索、重排、引用、删除和重建。上传完成不等于可检索。并发上传、取消、模型切换、删除与恢复不会产生错配索引或跨工作区召回。全文检索与向量检索按能力组合，不把特定数据库扩展设为 SQLite 功能缺失的理由。

长期记忆是可查看、纠正和遗忘的派生记录，与知识文档、会话摘要分开。默认不自动学习跨群、跨人或敏感信息；记录来源、作用域、有效期和置信状态。删除或撤权必须传播到索引和缓存，备份保留期及第三方数据边界如实说明。

降低检索权重、归档、停用和删除是不同操作；可固定重要记忆，长期事实不因短期未召回默认永久删除。恢复归档时同时恢复可见状态和获准检索资格，而非只把数据库记录放回去。

媒体覆盖图片、语音、音频、视频、文件、引用、转发和平台原生组件。限制字节、解码尺寸、持续时间、页数与历史常驻内存；处理失败可解释并保留安全的文本反馈。支持可恢复上传、受控转换、带鉴权预览和取消。附件按授权范围保存，不能因为路径随机或位于共享目录的子目录就声称隔离。

MCP 需要连接健康、初始化超时、自动重连、动态能力、凭据刷新和结果上限。服务离线不能拖垮核心，重连不能重放不确定的写操作。技能资源读取、工具调用和任意代码执行分别授权；读取一个只读说明文件不强制启动完整执行沙箱。

## 10. 前端与桌面

前端重新设计，采用“安静的工作台，明确的运行状态”作为整体方向。参考 particle-sculpture-skill 的可辨识几何、克制动作、主题角色与可访问降级方法；使用原创构图与主体，不直接套用其演示首页。

品牌展示页可使用由疏密粒子组成的抽象折线雕塑，表达消息进入、执行和返回。工作区内用稳定的 DOM 内容、紧凑列表和清楚的状态说明，不让粒子背景覆盖聊天、表格、配置或错误提示。粒子不是实际运行遥测，不能用随机活动伪装系统在工作。

主要入口：工作区切换、对话、运行与收件箱、知识和记忆、计划任务、机器人与渠道、模型、插件，以及成员/设置/审计。用户只看到获准入口，服务端仍独立鉴权。安装插件后导航根据真实能力变化，卸载立即撤销入口；失效插件仍有诊断与恢复入口。

聊天支持流式与完整回复、工具轨迹、失败重试、编辑分支、模型切换、附件、检索引用、草稿、搜索、分页历史和后台通知。重新连接按游标恢复已授权事件；不能把另一个会话的流或旧页面响应写入当前页面。

支持中文和英文、浅色和深色、键盘操作、屏幕阅读器、320px 窄屏和桌面布局。尊重减少动态效果、节省流量和低性能设备设置。动画可暂停、离屏停止、卸载清理；主要操作不依赖 Canvas、悬停或颜色。

原生桌面使用 Tauri 路线和独立 rstrbot 后端，支持 Linux、Windows、macOS 安装、启动、退出、升级和卸载。必须验证 sidecar、权限、数据保留和完整进程树回收。提供构建工程不等于提供通过验收的安装器。

## 11. 工程质量与依赖策略

Rust 质量标准参考 BeautifulRust：用明确类型表示身份、状态、单位与失败；公共 API 最小化；应用部分保持直白，SDK 才承担稳定抽象；不为了通过借用检查而无意义复制；不机械照搬其他语言的对象层级。

失败输入不能导致核心 panic。取消穿过插件、网络、渲染与数据库等待；资源有界；异步执行不被长时间 CPU 或阻塞 I/O 占住。共享锁范围短，持锁期间不调用第三方回调。必须使用不安全代码时集中封装、说明不变量并针对实际平台验证。

选择实施当时可核验的稳定工具链和受维护依赖，提交可重现锁文件。不要在需求文档中假称某个未经核实的版本“最新”。mise 管理开发工具，uv 管理 Python 环境。格式化、严格静态检查、测试、文档、依赖风险和许可证检查进入 CI，不能靠放宽门槛制造通过。

## 12. 发布验收

验收矩阵至少包含 SQLite/PostgreSQL × Valkey 关闭/开启，以及 Linux/Windows/macOS 的真实原生运行。测试用例覆盖多人越权、同名资源、并发写入、取消、重复事件、旧任务迟到、断线、重启、磁盘满、依赖崩溃、备份恢复与不确定副作用。

四种 SDK 使用同一协议验收；旧版、OpenCode、Pi 插件以冻结版本的真实样本验证发现、加载、事件、工具、媒体、后台推送和清理。分别公布通过、部分通过、失败和未执行，不能把导入成功视为完整兼容。

性能用固定硬件、数据集、并发和运行时组合测量。核心空闲内存、插件额外内存、队列等待、模型时间、投递时间、落库时间和前端渲染分别报告。轻量目标不能通过关闭权限、丢日志、忽略持久化或减少功能伪造。

完成的定义是：指定版本有可复现构建、真实 CI 运行链接、测试回执、原生安装与升级验证，以及准确的剩余限制。没有实际运行证据时，状态只能是“设计完成”“实现待验收”或“环境未验证”。

## 13. 范围与优先级

P0：身份和数据隔离、初始化安全、完整性、可控取消、工具副作用、插件撤权、可靠投递与恢复边界。P1：可日常使用的完整对话、四种 SDK、双数据库、插件生态、知识库、任务、前端和桌面闭环。P2：高级编排、可分享聊天、更多专用供应商、可选语音持续交互和多节点扩展。

第一阶段的 215 个需求族与 287 个验收条目全部保留在追踪附件中。按用户可见结果重组，内部实现允许重新设计。原有 MySQL 候选由明确的 SQLite/PostgreSQL 选择取代；中心插件市场不再是运行前提。特殊供应商、平台和高级功能可分批交付，但延期项必须保留，不能以“架构支持”标成已实现。

优先构建一条可验证的垂直路径：建立两个用户 → 各自工作区 → 安装同一个插件的隔离实例 → 接入模型和平台 → 执行工具并投递 → 重启恢复 → 验证相互不可见。之后逐批补足媒体、知识、任务、兼容与跨平台范围。

同一工作区还须包含所有者与普通成员：各有私有会话，共享一个获准代理和知识库。列表、搜索、诊断、事件流和普通工作区导出都不能隐式包含他人的私有内容；额外管理访问须有明确授权和审计。

交付应包含可运行产品、接口与插件开发文档、迁移/恢复文档、需求到测试的追踪记录。具体代码组织由实现者按这些契约和成熟最佳实践决定；本提示词不要求沿用旧类名、旧目录或旧数据库结构。

### 工作台与导航

工作区主导航提供两种可切换布局：左侧纵向侧栏、顶部横向导航栏。切换入口清楚可见，偏好持久保存；当前页面、工作区和权限过滤在两种布局间一致。侧栏和会话列表可手动折叠/展开；在窄屏与聊天阅读时可按滚动方向自动收起和恢复，但不能遮住焦点、输入框、弹窗或当前操作，也不能改动聊天历史阅读位置。

### 导航视觉复核（2026-10-28）

顶栏模式不得把所有页面摊成横向链接，也不得让分组在热更新、窄屏或长标签下挤压、纵向拉伸或造成整页横向滚动。桌面采用品牌、当前页面、工作区、带图标的分组菜单和账号操作组成的紧凑导航带；组名使用当前语言的自然大小写，当前分组清楚但克制地高亮。中等屏宽与手机将页面导航和工作区选择收进导航抽屉，顶栏只保留当前页面、抽屉入口及常用控件；不得在手机上挤成多列小按钮。每次改动后须重新载入真实页面，按桌面、平板和手机宽度检查内容溢出、当前页面辨识、菜单位置、键盘操作和触控空间。

### 模型与渠道配置

优先重做“添加模型”和“添加渠道”流程：按步骤或分组显示字段，解释每项用途、必填条件、保存后影响、凭据保留/清除规则、连接测试范围和失败后的下一步。能够从真实能力、协议或后端数据枚举的选项使用下拉、单选或多选，并说明默认值；无法安全枚举的地址、模型 ID、密钥和用户自定义内容保留自由输入，同时提供准确格式、示例、范围和验证，不伪造供应商或能力选项。时区、计划频率和常用数值提供有来源的选择项与清楚的自定义入口。保存、测试、连接、启用和实际运行分别呈现真实状态。
