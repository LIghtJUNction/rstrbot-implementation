## 1.18 会话模型选择与数据边界

每个会话恢复其最近一次已接纳发送所用且当前用户仍有权限的模型；增加新模型、导航、切换会话、刷新和重启不能静默改成其他模型并发送历史。选择器可明确切换，本次选择不影响其他会话；读取迟到、模型删除或撤权不得覆盖用户正在操作的选择。旧会话未保存模型、权限不可确认、模型不存在或存储异常时显示明确待选择状态并禁止发送，不能猜测或回退到列表第一个。持久记录与用户消息/运行接纳同一原子事务，拒绝、取消或幂等重放不能污染选择；共享会话不得向其他成员泄露私有模型身份；核心拒绝将私有模型用于共享会话，界面只列可供共享会话使用的模型。验收见 TEST_FEEDBACK 和 RSTRBOT-24。

RFB-006 实测：服务端已接纳而浏览器丢失确认，刷新后重新发送同一草稿会新建第二条消息并再次调用模型。保存每个已认证用户、实例、工作区、会话的待确认请求标识和原始完整发送参数，先持久化后派发；刷新、导航、重启后明确提示可能已送达，手动继续原请求必须复用完全相同参数和键，服务端原子幂等保持单次接纳。不同内容/模型/代理不能冒充原请求，必须先让用户核对并显式开始新意图；不自动重发，不泄露其他账号草稿，拒绝、撤权和结果未知不伪称成功。浏览器不能可靠持久化时明确限制与恢复途径，不得声称跨刷新安全。验证实有两次接纳及下游调用账本、确认丢失与真正未发、改模型/代理/正文、失败、注销切换账号和会话、迟到确认与新草稿、存储拒绝及重启。详见 RSTRBOT-26。

## 1.21 多标签页待确认请求

RFB-007 实测两个标签页对同会话交错操作时，旧确认框可删除另一标签页刚产生的新待确认记录。读取、创建和清除待确认意图必须在同浏览器同来源、用户、工作区及会话范围内协调；确认操作只作用于打开对话框时所确认的确切记录，过期时保留新记录并说明。其他标签页变更时界面更新；协调能力或存储不可用时安全暂停并说明恢复方式，不能伪称已发送。验证并发创建、不同请求、同请求、旧确认、迟到回执、重载、账号/会话隔离与权限撤销；服务器仍负责实际幂等和权限。设备间协调未完成不得承诺。验收见 RSTRBOT-27。

## 1.22 知识引用原文保留

RFB-008 本地实测：知识文档删除后，检索已不返回该文档，但旧对话与运行的引用元数据仍带整段源文本。模型调用可接收当前获准的检索片段，对话及运行记录只持久保存引用定位信息，不额外复制原文；所有受控历史、运行和事件响应也须去除旧记录内的引用原文。需验证现有旧数据读取、删除后刷新、原始模型上下文仍可获得授权文本。模型已生成的回答、旧数据库和备份中的历史副本无法由此保证抹除；在途删除/撤权竞争和旧数据物理清理均须另行验证，不得冒称已解决。验收见 RSTRBOT-28。

## 1.23 在回答中核对资料

RFB-009 实测对话已获取来源元数据但没有查看入口。助手消息须列出“检索到的资料”，说明候选资料不代表模型实际使用；点击时重新向服务端请求当前来源，核对用户权限、资源类别、启用状态、来源摘要、索引版本、分块标识及 UTF-8 字节范围，一致才展示原文并突出确切片段。来源修改、删除、撤权、停用或数据不一致时不显示旧原文，说明无法核对；网络失败可重试且不显示旧缓存。关闭、切换会话/账户/工作区与迟到响应不得留下跨身份原文。保留长文本、键盘和窄屏可用；不把候选材料标成模型已引用。验收见 RSTRBOT-29。

OpenClaw #157827 提醒：未来若将多来源证据合并为摘要或记忆，每个非连续片段必须携带实际对应的全部来源及版本/位置；不能将合并后的全文归给第一个引用。无法维持可核对的映射时不得发布或提升该派生内容；旧数据不得通过猜测重分配。该问题在本项目尚无自动派生实现，按 RSTRBOT-30 验证，不把上游报告当作本地复现。

## 1.24 长时间运行的检索索引更新

OpenClaw #16844 的历史报告提示，索引写入已完成但常驻读取连接或位置缓存仍停留在旧快照时，可能静默漏掉新资料。索引发布完成后，后续检索需基于已发布的代次和新鲜读取视图，来源、结果与位置映射一致；后台重建未完成则显示处理中，不得冒充新索引已就绪。版本不一致或无法定位来源时应明确降级/失败，不能静默丢弃并伪称完整结果。测试 SQLite WAL、多连接/外部索引进程、更新与并发查询、删除和重启；现有同步词法路径的单实例结果不能证明外部索引路径或 PostgreSQL/Valkey 已通过。见 RSTRBOT-31。

RFB-010 本地故障注入：已就绪文档分块与原文不符时，检索返回空且未标降级，聊天仍发起模型调用。核心必须对获准、启用且 ready 的异常索引显式报告不一致；聊天在完整结果不可保证时失败并给当前语言的修复提示，列出当前对话受众有权访问、需要重新保存的资料名称，不能向模型发送误导性的无来源上下文。用户修正并重新保存文档后可重新索引恢复；不得暴露无权文档内容或身份。详见 RSTRBOT-32。

## 1.25 计划运行的真实结果

RFB-011：真实一次性计划的模型请求失败，运行记录标为 failed，计划却显示 completed。一次性计划结束状态必须区分完成、失败与取消；重复计划保留未来调度状态并明确展示最近一次运行的真实结果，不用计划本身可继续运行掩盖失败。任务列表和详情使用当前语言显示最近结果；对 in-flight 重启后的待核对状态说明不会自动重发，并提供获准运行记录的直接入口，未确认的副作用不能因查看或启用而自动重放。历史数据存在时按实际 last_result 展示，不伪造结果。见 RSTRBOT-33。
